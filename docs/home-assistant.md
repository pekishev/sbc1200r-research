# ESPHome и Home Assistant

## Платы и статус

Основной `esphome/sbc1200r.yaml` теперь предназначен для **ESP8266 DevKit / NodeMCU v2 / ESP-12E (4 MB)**, RX **D7/GPIO13**. Исходный ESP32-CAM-вариант сохранён отдельно как `esphome/sbc1200r-esp32cam.yaml`. Аппаратная проверка с MPPT ещё не проводилась ни для одного варианта.

Основной ESP8266-вариант прошёл проверку конфигурации и полную сборку в ESPHome **2026.11.0**, Arduino framework **3.1.2-esphome.4**. Приложение: **380233 байта**, RAM: **30876 байт** по отчёту сборки. В используемой библиотеке ESPAsyncWebServer/веб-OTA есть предупреждения об устаревшем `beginResponse_P`; ошибок компиляции нет. UART-парсер и публикация датчиков сохранены.

Исходный [ESP32-CAM вариант](../esphome/sbc1200r-esp32cam.yaml) прошёл проверку конфигурации и полную сборку в ESPHome **2026.11.0**, ESP-IDF **5.5.6**, для `esp32cam` (4 MB). Размер приложения: 811863 байт; RAM: 45100 байт по отчёту сборки. Прошивка на ESP32-CAM в рамках исследования не загружалась, аппаратной проверки интеграции пока нет.

UART-парсер проверяет заголовок и сумму, использует скользящее окно для восстановления синхронизации. Примерно 4 кадра/с ограничиваются публикацией показаний не чаще раза в секунду. Через 5 секунд без валидного кадра числа становятся `unknown`, а UART Online выключается.

## Подготовка и первая установка

1. Скопировать `esphome/sbc1200r.yaml` в каталог своего ESPHome Device Builder.
2. Рядом создать собственный `secrets.yaml` по [примеру](../esphome/secrets.example.yaml). Пароли и `secrets.yaml` в Git не добавлять.
3. Проверить, что плата — ESP8266 NodeMCU v2 / ESP-12E с 4 MB flash, а D7/GPIO13 свободен. Для ESP32-CAM выбрать отдельный YAML и не использовать microSD.
4. Собрать и установить через USB-UART.
5. Подключить MPPT по [схеме](hardware.md), включить плату и проверить её IP в логах/роутере.

```sh
esphome config esphome/sbc1200r.yaml
esphome compile esphome/sbc1200r.yaml
```

Для ESP8266 DevKit использовать встроенный USB-разъём; MPPT при первой прошивке можно оставить отключённым. После установки подключить сигнал MPPT к D7 через делитель.

Для ручной первой прошивки **ESP32-CAM-варианта** CP2102 нужно отключить от MPPT: TXD адаптера → U0R ESP32-CAM, RXD → U0T, GND → GND. UART-уровни 3,3 В, питание платы — стабильные 5 В. GPIO0 соединить с GND на время входа в загрузчик и сбросить питание; после прошивки убрать перемычку и снова сбросить плату. GPIO13 используется для MPPT при работе; U0R/U0T — для первой прошивки.

В примере используется обычный Native API без шифрования и OTA без пароля, как в исходном локальном стенде. Для своей установки можно настроить [API encryption](https://esphome.io/components/api/) и [OTA password](https://esphome.io/components/ota/esphome/), храня значения в secrets. Не выставлять эти сервисы напрямую в интернет.

## Добавление в HA

Настройки → Устройства и службы → Добавить интеграцию → **ESPHome**. Указать IP платы или `sbc1200r.local`, порт 6053; либо добавить автоматически обнаруженное устройство.

| Сущность | Единица | Источник |
|---|---|---|
| Input Voltage | V | UART |
| Output Voltage | V | UART |
| Output Current | A | UART; отнесение к выходу поддерживается сравнением мощности |
| Output Power | W | `Vout × Iout` из одного кадра |
| UART Online | Вкл/выкл | Валидный кадр за последние 5 секунд |

## Энергия

В HA создать помощник **Интеграл** от Output Power: префикс `k`, время `h`, метод трапеций, максимальный подынтервал 1 минута. Получится собственная оценка энергии в кВт·ч с начала наблюдения; помощник сохраняет накопленное значение при перезапуске HA.

Это не штатный счётчик MPPT. Пропуски телеметрии/работы HA ограничивают точность. Температура и штатные кВт·ч пока не декодированы.

Источники: [интеграция ESPHome](https://www.home-assistant.io/integrations/esphome/), [Integral](https://www.home-assistant.io/integrations/integration/), [UART debugger ESPHome](https://esphome.io/components/uart/).
